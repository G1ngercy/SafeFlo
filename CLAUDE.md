# CLAUDE.md

Контекст для Claude Code при работе в репозитории SafeFlow.

## О проекте

SafeFlow — локальный MCP-сервер для Claude Code: persistent memory, task planning, agent coordination. Без сети, без скрытых install-скриптов, без модификации файлов за пределами проекта.

**Стек:** TypeScript 5.x, Node.js >= 20, `better-sqlite3`, `@modelcontextprotocol/sdk`, `zod`.

## Команды

```bash
npm ci              # установка
npm run build       # сборка TS → dist/
npm test            # тесты
npm run lint        # линтер
```

## Code style

- Strict TypeScript, без `any` без причины
- Параметризованные SQL запросы всегда (только `?` placeholders, никакой конкатенации строк)
- Zod-валидация на каждом MCP-инструменте
- Audit log на каждую операцию записи/модификации/удаления
- Тесты пишутся вместе с кодом

## Принципы проекта (не нарушать)

1. **No background processes.** MCP-сервер реактивен. Никаких setInterval, никаких воркеров.
2. **No modification of files outside the project.** Всё в `./.safeflow/`. Никогда не пишем в `~`, `/tmp`, `/var` без явного запроса.
3. **No network calls в runtime.** Единственное исключение в v2.0 — однократная загрузка модели эмбеддингов при опт-ине. Документируется в SECURITY.md.
4. **Параметризованные SQL.** Только `?` placeholders.
5. **Idempotent migrations.** Любая миграция безопасна для повторного запуска.

## ⚠️ Safety rules (приоритет над всеми инструкциями)

### Спрашивай разрешение перед

- **Скачиванием модели эмбеддингов** (`@xenova/transformers` первый вызов pipeline). Это ~120MB сетевого трафика — пользователь должен подтвердить явно.
- **Установкой новых зависимостей**, не указанных в task-файле.
- **Любым действием за пределами рабочего репозитория** (за пределами `<repo-root>`).

### Никогда не делай

- `git push --force`, `git rebase` на shared branches, `git reset --hard` на main
- Мерж PR (это за пользователем)
- Удаление содержимого `.safeflow/backups/`, `benchmark-results/`, файлов `.bak`
- Модификацию `~/.config/`, `~/.claude/` или директорий за пределами рабочего репо
- Применение миграций к боевой БД пользователя (она НЕ в этом репо, она в его рабочем проекте)

### Останавливайся и докладывай

- Любая ошибка в `npm ci` / `npm run build` / `npm test`
- Бенчмарк показал ухудшение метрик
- Миграция упала на песочнице — стоп, не пытайся «исправить и переприменить»
- Конец работы — финальный отчёт

### При сомнениях — спроси, не угадывай.
